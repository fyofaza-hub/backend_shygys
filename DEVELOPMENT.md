# Creative Shygys

Backend цифровой экосистемы креативных индустрий Восточно-Казахстанской области. FastAPI и Pydantic v2 публикуют контракт для Next.js по URL `/openapi.json`. PostgreSQL 16 с PostGIS хранит каталог, рабочие версии и географию. ARQ использует Redis, а задачи сначала сохраняются в PostgreSQL. Оригиналы и WebP-превью хранятся в закрытом S3 bucket.

## Локальный запуск

Подготовьте конфигурацию. Команды ниже записывают новые случайные значения в локальный `.env`. Если файл уже существует, заполните соответствующие поля вручную.

```bash
cp -n .env.example .env
python3 - <<'PY'
from pathlib import Path
from secrets import token_hex
path = Path(".env")
lines = path.read_text().splitlines()
keys = {"POSTGRES_PASSWORD", "JWT_SECRET", "S3_SECRET_KEY"}
path.write_text("\n".join(
    key + "=" + token_hex(32) if (key := line.removesuffix("=")) in keys and line.endswith("=") else line
    for line in lines
) + "\n")
path.chmod(0o600)
PY
docker compose up --build -d
docker compose exec api python -m scripts.manage bootstrap-admin admin@example.com
curl -f http://localhost:8000/health/ready
curl -f http://localhost:8000/openapi.json -o /tmp/creative-shygys-openapi.json
```

Swagger UI доступен на `http://localhost:8000/docs`, Mailpit на `http://localhost:8025`, консоль MinIO на `http://localhost:9001`. Начальный суперадминистратор создаётся один раз. Для защищённых запросов передавайте `Authorization: Bearer <token>` после входа по `POST /auth/login`. Токен короткоживущий, роли и блокировка пользователя проверяются в БД на каждом запросе. Не сохраняйте токены в репозитории или логах.

## Справочники

Импортируйте согласованный XLSX из 43 ОКЭД. Формат первой вкладки содержит заголовки `code`, `kk`, `ru`, `en`. Храните `code` как текст, включая ведущие нули. Повторный запуск с теми же данными безопасен. Изменения импортируйте под новой версией.

```bash
docker compose cp approved-oked.xlsx api:/tmp/approved-oked.xlsx
docker compose exec api python -m scripts.manage import-oked /tmp/approved-oked.xlsx --version v1
```

Категории, районы, населённые пункты и подтверждённые площадки настраиваются через `/admin/references/*` и `/admin/places`. Центры районов и населённых пунктов загружайте из согласованного источника WGS84. Для районов и населённых пунктов предусмотрена выдача загруженных границ через `/map/boundaries/{kind}`. До импорта справочников тестовые данные можно заводить через OpenAPI.

## Контракт фронтенда

| Назначение | Маршруты |
|---|---|
| Каталог и публичный профиль | `GET /creators`, `GET /creators/{slug}` |
| Карта и слои | `GET /map/creators`, `/map/places`, `/map/events`, `/map/config` |
| Работы, проекты, новости, поддержка | `GET /portfolio`, `/projects`, `/articles`, `/events`, `/opportunities` |
| Личный кабинет и черновики | `/me`, `/me/creator`, `/me/portfolio`, `/me/projects`, `/me/items/*`, `/me/media` |
| Согласия и уведомления | `/me/consents`, `/me/notifications`, `/me/data-requests/{kind}` |
| Модерация | `/moderation/cases` и маршруты назначения, решения, скрытия и восстановления |
| Резидентство | `/me/residencies`, `/center/residencies`, `/admin/residencies` |
| Редакция и перевод | `/editor/*`, `/translations/{kind}/{entity}` |
| Агрегаты и отчёты | `/analytics/dashboard`, `/analytics/metrics`, `/analytics/export/{fmt}`, `/analytics/gis-export` |
| Поиск | `/search` |

Списки принимают `page` и `limit`. Ограничение на `limit` равно 100. Каталог и карта используют одинаковые фильтры. Передавайте несколько категорий и кодов повторяющимися параметрами `category` и `oked`. Карта дополнительно принимает `bbox=west,south,east,north` и `zoom`, а кластеры строятся в Web Mercator. Координаты в ответе отдаются в WGS84. Один публичный маркер содержит `creator_id`, `slug` и `accuracy`. У кластера есть `id` и `count`. Экспорт GIS включает только опубликованные координаты с отдельным согласием.

В карточке креатора отдельно передаются `legal_status`, `residency`, `moderation_status` и `publication_status`. Поля языка принимают объект с ключами `kk`, `ru`, `en`. Пустая строка означает незаполненный перевод. После отправки первой версии публичный URL становится доступен только после одобрения. Изменения уже опубликованной версии автоматически создают заявку. Рабочее состояние версии доступно владельцу и модератору. После загрузки фотографии опрашивайте `GET /me/media/{id}` до состояния `ready`, затем привязывайте её к материалу. Публичные превью доступны по `/media/{id}/320` и `/media/{id}/960` после появления ссылки на фото в публичной версии.

## AlemAI Plus и Browserless

Укажите `ALEMAI_BASE_URL` с префиксом OpenAI-compatible API, серверный `ALEMAI_API_KEY` и `AI_TRANSLATION_MODEL` из вашего аккаунта. Укажите `AI_PROVIDER=alemai`. Прежнее имя `ALEMAI_TRANSLATION_MODEL` тоже поддерживается. Для перевода поддерживаются идентификаторы на основе Gemma 4 и Qwen 3.8. Qwen 3.6 отклоняется. Перевод запускается явно двумя заданиями, привязанными к хешу исходного текста. Для публикации статьи требуется ручная проверка языковых версий или обоснованное исключение администратора. `ALEMAI_KK_MODEL` можно назначить на доступную в аккаунте KazLLM или AlemLLM. `AI_GLOSSARY` принимает JSON-словарь.

Для опционального переранжирования лексических кандидатов задайте Embedder, Reranker и его полный URL. Вызов выполняется только при `semantic=true` и наличии явного разрешения на внешнюю обработку кандидата. Для профилей это согласие `ai_search`, для мер поддержки — настройка редактора. При сбое провайдера сохраняется лексическая выдача. Настройте `BROWSERLESS_URL` и `BROWSERLESS_TOKEN` для PNG/PDF. CSV и XLSX формируются локально.

## Проверка и развёртывание

```bash
uv sync --locked
uv run ruff check .
uv run python -m pytest
```

Интеграционные тесты создают записи в изолированной тестовой БД. Передайте тестовые `DATABASE_URL` и `REDIS_URL`, примените `uv run alembic upgrade head` и запустите `SHYGYS_INTEGRATION=1 uv run python -m pytest`.

Compose предназначен для локальной разработки. Перед промышленным развёртыванием используйте отдельные роли для миграций и исполнения. Исполняемой роли требуется `SELECT/INSERT` на `audit_events` и права CRUD только на прикладные таблицы, с которыми она работает. Владелец БД и роль миграций должны быть отделены от аккаунта приложения. Разместите API за HTTPS reverse proxy, настройте доверенные адреса прокси, лимит тела запроса и конкретные CORS origins. План резервного копирования включает PostgreSQL и закрытый bucket. Восстановление проверяйте на отдельном стенде до ввода в эксплуатацию.

## Приёмка

Матрица AC-01–AC-30, команды и результаты нагрузки на 10 000 профилях доступны в [ACCEPTANCE.md](ACCEPTANCE.md).

Для защиты загрузок настройте `CLAMAV_HOST` и `ENABLE_CLAMAV=true`. В обязательном режиме недоступность сканера останавливает загрузку. Приложение проверяет файл до отправки оригинала в S3.

Для запуска с реальными данными нужны исходный XLSX ОКЭД, утверждённые геоданные ВКО и параметры внешних сервисов. Администратор может оформить запрос пользователя на выгрузку и закрытие аккаунта. Закрытие отзывает доступ и согласия, а окончательное удаление следует выполнять по утверждённой политике хранения.

Поддерживаются команды организаций, предварительный просмотр слияния дублей, выставки, тематические коллекции и маршруты площадок, заявки на сотрудничество, фильтрация мер поддержки и пресеты BI. Слияние архивирует профиль-дубль, сохраняя его историю. Выбранные поля можно перенести в очередную версию основного профиля. Работы, проекты, организации, контакты и права доступа остаются привязанными к исходным владельцам.

Отдельные продуктовые гипотезы WOW, включая AI-помощника портфолио и персонализированную витрину достижений, требуют дальнейшей реализации и приёмки. Браузерная приёмка выполняется совместно с проектом Next.js.

## Контракт профилей и каталога /api/v1

Исторические маршруты доступны для действующих клиентов. Для новых интеграций используйте `/api/v1/creators` и `/api/v1/map/creators`. Оба маршрута принимают `q`, `category_id`, `oked_code`, `district_id`, `locality_id`, `legal_status`, `is_resident`, `open_to_collab`, `page` и `limit`. Для нескольких категорий или ОКЭД повторяйте соответствующий query-параметр. `q` использует полнотекстовый поиск по одобренным профилям и опубликованным проектам.

Создайте первый черновик со slug через `POST /api/v1/me/creator`. `PATCH /api/v1/me/creator` изменяет только указанные поля, включая отдельные языки. Изменения профиля ожидают отдельного `POST /api/v1/me/creator/submit`. Настройки публичности контактов начинают действовать сразу. При выборе `accuracy=district` публичные координаты берутся из справочника района, идентификаторы населённого пункта и площадки скрываются. `exact` требует подтверждённой публичной площадки. QR по `/api/v1/creators/{slug}/qr` направляет на `FRONTEND_URL/creators/{slug}`.

Модераторы работают с общей очередью. Куратор может читать и модерировать заявки профилей, связанных с его центром через действующее или рассматриваемое резидентство. Куратор рекомендует присвоение статуса, администратор подтверждает его, куратор может отозвать статус в своём центре. Все решения записываются в аудит.

Файл [openapi.json](openapi.json) сгенерирован из приложения. Актуальная схема работающего сервера доступна по `GET /openapi.json`.

## Медиа, портфолио и проекты /api/v1

`POST /api/v1/media/upload` принимает multipart с полем `file` (JPEG, PNG или WebP) и необязательным `rights`. Ответ `202` содержит идентификатор, MIME, размер, размеры изображения, статус и объект `variants` с относительными URL оригинала, thumbnail и medium. Опрос `GET /api/v1/me/media/{id}` показывает готовность WebP. До `ready` превью ещё недоступны. URL в `variants` требуют Bearer-токен владельца. Публичные превью по `/api/v1/media/{id}/320` и `/api/v1/media/{id}/960` появляются, когда на файл ссылается публичная версия. Исходники с метаданными остаются в закрытом bucket. Для подключения S3 задайте endpoint, имя bucket, регион и серверные ключи.

В личном кабинете используйте `GET/POST /api/v1/me/portfolio`, `GET/PATCH/DELETE /api/v1/me/portfolio/{id}` и аналогичные маршруты `projects`. Создание сохраняет черновик, `POST …/{id}/submit` ставит его в очередь. Правка уже опубликованной работы или проекта отправляется на проверку сразу. Галерея принимает `images` с полями `media_id` и `sort_order`; существующий контракт `media_ids` сохраняется. В публичном списке работ `sort` принимает `newest`, `author` или `popular`. Просмотры работ регистрируются через `POST /api/v1/analytics/visits` с `kind=portfolio_item`.

`PUT /api/v1/me/portfolio/pins` принимает до трёх ID собственных публичных работ в порядке закрепления. Публичная карточка креатора содержит `pinned_works` и первую страницу `projects`, связанные проекты доступны также через `GET /api/v1/projects?creator_id={id}`. При создании проекта можно задать стабильный `slug`. Приглашённый участник находит проект через `GET /api/v1/me/project-invitations` и подтверждает его по `POST /api/v1/me/projects/{id}/confirm-participation`. Публичный проект доступен по `GET /api/v1/projects/{slug}`.

Ленты контента доступны по `/api/v1/articles`, `/api/v1/events`, `/api/v1/opportunities` и `/api/v1/spaces`. Для календаря выберите `calendar=upcoming|past|all`, для пространств передайте тип в `kind`.

## Карта, CMS и перевод /api/v1

- `GET /api/v1/map/points` отдаёт отдельные точки, `GET /api/v1/map/clusters` группирует те же результаты по `zoom` и `bbox`. Для `layer=creators` применяются все фильтры каталога. У карты дополнительно действует ограничение видимой области. Отдельные запросы с `layer=spaces|workshops|galleries|events` возвращают слои площадок или предстоящих событий. Радиусный поиск по подтверждённым публичным координатам доступен по `/api/v1/map/creators/nearby`, тепловая карта по `/api/v1/map/heatmap` для аналитика и администратора скрывает ячейки с менее чем пятью точками. GIS-экспорт требует активного согласия на выгрузку.
- Редакторы управляют опубликованными и черновыми материалами через `/api/v1/editor/articles`, `/editor/events`, `/editor/opportunities` и `/editor/spaces`. Дата `publish_at` передаётся при публикации. Галерея статьи сохраняет порядок массива `gallery` (изображения и внешние видео), максимум 10 элементов. `cover_id` задаёт обложку, `meta_tags` хранит локализованные SEO-метатеги. История изменений доступна по `/editor/history/{id}`. Для таблиц контента доступны CSV/XLSX, персональные пресеты фильтров и массовое архивирование. Администратор сохраняет порядок секций главной через `/editor/home/layout`.
- Справочники `categories`, `districts`, `tags` и `oked` доступны в CMS по `/api/v1/editor/dictionaries/{kind}`. Новую версию ОКЭД публикуют целиком через `/editor/oked-versions`. Нужны ровно 43 уникальных кода с названиями на всех трёх языках. Версия остаётся читаемой в CMS после снятия с публичной выдачи.
- `POST /api/v1/translations/generate` ожидает `entity_id`, `source_locale` и `external_processing_approved=true`. По умолчанию `entity_type=article`, API создаёт задания для двух целевых языков. `overwrite_human_reviewed=true` разрешает заменить конкретную проверенную ревизию. Ручная правка, сохранённая после такого подтверждения, остаётся защищённой. Глоссарий можно расширить через `AI_GLOSSARY`, резервный идентификатор Gemma 4 задаётся через `ALEMAI_FALLBACK_MODEL`. Структурированные личные данные исключены из payload. Перед разрешением внешнего перевода редактор проверяет свободный текст, поскольку серверные проверки контактов и адресов работают по шаблонам.


## Локальные сервисы тестового стенда

Конфигурация `.env` подключает MinIO по `http://127.0.0.1:9000`, Mailpit SMTP по `127.0.0.1:1025` без STARTTLS и внешний Browserless по `https://production-sfo.browserless.io`. Ключи остаются в игнорируемом `.env` с правами 0600. Mailpit принимает тестовые письма локально; веб-интерфейс доступен по `http://127.0.0.1:8025`.

В этой среде доступ к системному Docker socket закрыт. Mailpit запускается из официального образа `ghcr.io/axllent/mailpit:v1.27.4` через локальный Podman и user namespace. Runtime размещён в `~/.local/share/shygys-services`, отдельные каталоги `mailpit` и `minio` сохраняют данные между перезапусками. MinIO собирается из официального Go-модуля тега `RELEASE.2025-04-22T22-12-26Z`.

Установленный runtime запускается из корня репозитория следующими командами в отдельных терминалах.

```bash
uv run python -m scripts.run_test_services
uv run python -m scripts.init_bucket
uv run python -m scripts.run_demo
```

Если бинарник MinIO требуется пересобрать, при установленном Go выполните следующую команду.

```bash
GOTMPDIR="$HOME/.local/share/shygys-services/go-tmp" GOBIN="$HOME/.local/share/shygys-services/bin" go install github.com/minio/minio@RELEASE.2025-04-22T22-12-26Z
```

Сквозная проверка реальных MinIO, SMTP и Browserless запускается через API.

```bash
uv run python -m scripts.check_real_services --require-browserless
```

Проверка создаёт отдельный тестовый аккаунт, проверяет письмо подтверждения, загрузку оригинала и два WebP, доступ к закрытым файлам, письмо о решении модерации и реальные PDF/PNG. JSON-протокол и отчёты сохраняются в `/tmp/shygys-real-services.*`.

Антивирус отключён через `ENABLE_CLAMAV=false`. При `ENABLE_CLAMAV=true` задайте `CLAMAV_HOST` и `CLAMAV_PORT`. Приложение отправляет оригинал в ClamAV командой INSTREAM перед S3. Недоступность обязательного сканера блокирует загрузку. Для Compose включите профиль `antivirus` вместе с переменной `ENABLE_CLAMAV=true`; штатно профиль не запускается.

```bash
ENABLE_CLAMAV=true docker compose --profile antivirus up -d
```
